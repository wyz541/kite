# Kite 截图隐私规则

## 结论

Kite 仓库不保存真实本机数据截图。
公开产品预览只允许使用合成目录、脱敏裁切图或合成数据完整窗口。

## 禁止内容

截图不得包含以下真实信息：

- Windows 用户名或 `/Users/<name>` 路径。
- `C:\Users\<name>` 路径。
- 真实本机磁盘容量或自定义卷名。
- 设备名称、主机名、IP 地址或序列号。
- 最近文件、搜索记录或页签名称。
- 未公开项目名称。
- 祖先目录中的其他项目名称。
- 可识别个人身份的预览内容、图片或元数据。

## 公开产品预览

- 从真实运行的 Kite 窗口截图。
- 使用只读合成磁盘镜像或隔离合成目录。
- 合成目录只包含虚构数据。
- 启动时隔离会话、收藏和界面配置文件。
- 可以展示完整窗口、系统标题栏、页签栏和地址栏。
- 完整窗口只显示合成目录、虚构标签和通用系统名称。
- 侧边栏只显示通用位置名称和合成收藏。
- 侧边栏不得显示真实自定义卷、真实收藏或磁盘容量。
- 不显示真实家目录、真实自定义卷名或祖先目录内容。
- 发布前完成目视隐私检查。
- 发布前用 OCR 检查全部可识别文本。
- 删除 PNG 文本元数据和定位元数据。
- 图片内容、OCR 结果和隐私规则不一致时，禁止提交。

## 存储规则

- 仓库默认忽略 `docs/screenshots/` 和图片文件。
- `assets/kite-icon-master.png`、`assets/kite-icon-preview.png` 和图标文件是允许的产品图片。
- `docs/images/kite-product-preview-sidebar.png` 是允许的公开产品预览图。
- 审查后的公开图片必须加入隐私检查允许列表。
- 截图源文件和中间截图只放本机临时目录，不提交。
- 发布包不包含截图目录。
- `build.ps1` 不复制截图到发布包。

## 历史清理

- 删除截图的普通提交不删除历史。删除截图必须重写全部引用。
- 重写后检查分支、标签和 PR 引用。
- 发现缓存对象时联系 GitHub Support 清除。
- 提交历史使用项目身份。提交历史不得包含个人邮箱或主机名。

## 性能报告

- 报告可以记录平台和架构。
- 报告不得记录具体设备型号。
- 报告不得记录核心数、内存容量和磁盘容量。
- 原始归档在发布前必须脱敏。
- 脱敏后重新计算归档校验值。
