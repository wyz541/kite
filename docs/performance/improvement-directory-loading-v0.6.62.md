# 目录读取性能优化

结论：目录读取改为每个目录项只执行一次元数据读取。三次同机 A/B 显示 1K、10K 和 50K 目录的 p50 与 p95 都下降。

## 1. 优化内容

修改文件：`src/fs.rs`。

- 使用 `DirEntry::metadata()` 获取目录项元数据。
- 删除普通文件和普通目录上重复的 `symlink_metadata` 调用。
- 符号链接仍执行额外的目标元数据读取。
- 隐藏项判断后再创建 `PathBuf`。
- 使用迭代器大小提示预分配结果向量。
- 保留符号链接目标类型和大小的原有语义。

## 2. 实验条件

| 字段 | 内容 |
| --- | --- |
| 平台 | macOS arm64 |
| 设备 | Apple M1 Max |
| 内存 | 64 GiB |
| 文件系统 | APFS |
| 配置 | `standard` |
| 构建 | release |
| 优化前 commit | `e7c8b47` |
| 优化后 commit | `7eda754` |
| 独立运行 | 3 次优化前，3 次优化后 |
| 目录交互样本 | 每场景 30 个 |

每个版本执行三次独立进程运行。比较使用三次运行中位数和噪声阈值。

## 3. 结果

| 目录规模 | 版本 | p50 ms | p95 ms | max ms | p95 抖动 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 1K | 优化前 | 4.152 | 4.617 | 5.618 | 1.9% |
| 1K | 优化后 | 3.227 | 3.871 | 3.962 | 11.0% |
| 10K | 优化前 | 33.811 | 38.107 | 43.639 | 14.3% |
| 10K | 优化后 | 28.731 | 31.185 | 34.634 | 8.2% |
| 50K | 优化前 | 200.939 | 220.473 | 236.898 | 5.6% |
| 50K | 优化后 | 164.517 | 178.037 | 183.284 | 1.9% |

## 4. 提升幅度

| 目录规模 | p50 变化 | p95 变化 | 判断 |
| ---: | ---: | ---: | --- |
| 1K | -22.3% | -16.2% | 通过噪声阈值 |
| 10K | -15.0% | -18.2% | 通过噪声阈值 |
| 50K | -18.1% | -19.2% | 通过噪声阈值 |

三个规模都显示稳定下降。50K 目录的 p95 从 `220.473 ms` 降到 `178.037 ms`。

## 5. 解释

普通目录项原路径执行以下读取：

1. `DirEntry::file_type()`。
2. `symlink_metadata()`。

优化后执行以下读取：

1. `DirEntry::metadata()`。
2. 仅符号链接执行目标 `metadata()`。

因此普通项目减少一次路径元数据读取。

## 6. 其它场景

同机比较中，冷内容索引和会话保存超过各自阈值。优化补丁不调用这两个路径。当前证据不能把变化归因于目录读取改动。

这两项保留为独立复核项，不写成性能回归。

## 9. 边界

- 测试未清理操作系统缓存。
- 数据来自一台 Apple M1 Max 和 APFS。
- Windows 性能提升仍需独立基准数据。
- 本报告只证明目录读取优化，不证明整个产品性能提升。
