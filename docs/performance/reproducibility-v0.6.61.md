# Kite 0.6.61 性能复现

结论：同一构建、同一设备和同一 `standard` 配置连续运行两次后，28/36 个场景的 p95 变化在 ±10% 以内。VCS、卷枚举和小文件操作仍需要更多运行次数。

| 范围 | 场景数 | 占共同测量场景 |
| --- | ---: | ---: |

p95 变化范围为 `-66.3%` 到 `+63.2%`。正值表示第二次运行更慢。

## 4. 超过 20% 的场景

| 功能域 | 场景 | p95 变化 | 分类 |
| --- | --- | ---: | --- |
| VCS 与菜单 | `git_dirty_status_100_files` | +63.2% | 变慢 |
| VCS 与菜单 | `git_clean_status` | +50.8% | 变慢 |
| 卷枚举 | `volume_enumeration` | -66.3% | 变快 |
| 页签与会话 | `load_session_20_tabs` | -21.8% | 变快 |
| 文件操作 | `move_small_file_tree` | -21.7% | 变快 |
| 文件操作 | `create_100_files` | +21.0% | 变慢 |
| 压缩 | `extract_tar_gz` | +20.1% | 变慢 |

这些变化来自相同构建。因此，单个 `+20%` 结果不能证明性能回归。

## 5. 解释

- Git 状态依赖外部 `git` 进程。进程启动和仓库扫描抖动会进入 p95。
- 卷枚举依赖系统设备状态和系统 API。结果受系统缓存影响。
- 小文件创建和移动受文件系统、后台索引和系统负载影响。
- Tar 解压受 CPU 调度和文件系统写入影响。
- 搜索、目录读取、内容索引、哈希和排序在两次运行中保持稳定。

## 6. 后续门槛

发布门槛不能直接采用单次运行的 `20%` p95 阈值。

下一阶段使用以下规则：

1. 对 VCS、卷枚举和小文件操作至少运行 3 次。
2. 使用三次运行的中位数比较版本。
3. 对超过阈值的场景再运行一次。
4. 只有重复出现的变慢才拆成性能修复 Issue。
5. 先积累多个发布版本的数据，再设置阻断阈值。

当前比较脚本只定位变化。脚本不判定根因，也不阻断合并。
